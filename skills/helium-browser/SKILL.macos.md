# Живой браузер Helium

Работаем в настоящем браузере пользователя: его профиль, его куки, его история.
Отдельный профиль не нужен и пользователь его не хочет. Helium — форк Chromium
153, запрет Chromium 136+ на `--remote-debugging-port` для дефолтного
user-data-dir он **не** применяет, поэтому живой профиль цепляется напрямую.

Инструментов два. `pagectl` — основной, он не выполняет JS на странице.
`rodkit` — запасной, у него есть `eval`, и именно поэтому он оставляет следы.

## Шаг 1. Поднять сессию

Проверить, жив ли порт:

```bash
curl -fsS http://127.0.0.1:9222/json/version >/dev/null && echo alive
```

Живой — переходить к шагу 2. Закрыт — **спросить пользователя**, можно ли
перезапустить браузер: перезапуск закроет все его вкладки. После согласия:

```bash
osascript -e 'quit app "Helium"'; sleep 3
open -a Helium --args --remote-debugging-port=9222
sleep 6
WS=$(curl -fsS http://127.0.0.1:9222/json/version | python3 -c 'import sys,json;print(json.load(sys.stdin)["webSocketDebuggerUrl"])')
PID=$(pgrep -f "MacOS/Helium --remote-debugging-port=9222" | head -1)
printf '{"pid": %s, "control_url": "%s", "base_url": "", "tab": ""}\n' "$PID" "$WS" >| ~/.rodkit/session.json
```

Готово, когда `pagectl tabs` печатает список вкладок.

## Шаг 2. Работать через pagectl

Бинари лежат в `~/go/bin/`, которого нет в PATH — звать по полному пути.

```bash
~/go/bin/pagectl tabs                    # список вкладок, * — текущая
~/go/bin/pagectl use 2                   # переключиться
~/go/bin/pagectl open <url>              # перейти в текущей вкладке
~/go/bin/pagectl newtab <url>            # новая вкладка

~/go/bin/pagectl snapshot                # что на странице, со ссылками [eN]
~/go/bin/pagectl find '<css|xpath|текст>'
~/go/bin/pagectl text                    # видимый текст
~/go/bin/pagectl shot page.png

~/go/bin/pagectl click e31
~/go/bin/pagectl type e29 'текст'
```

Рабочий цикл: `snapshot` → действие по ссылке → `snapshot` заново. Ссылки `[eN]`
живут до перехода на другую страницу; после навигации снимок протухает, и
`click` скажет об этом прямо.

Если элемента нет в снимке — искать `find`, он понимает CSS, XPath и простой
текст одним вызовом.

## Шаг 3. Закрыть порт

Когда работа закончена, предложить пользователю вернуть браузер в обычный режим:

```bash
osascript -e 'quit app "Helium"'; open -a Helium
```

Порт 9222 не требует авторизации: пока он открыт, любой локальный процесс
получает полный доступ ко всем залогиненным сессиям пользователя.

## Опасные места

**`rodkit stop` не запускать никогда.** Он шлёт SIGTERM в pid из `session.json`,
то есть убивает живой браузер пользователя вместе со всеми вкладками.

**`chrome://` через CDP не открывается** — `net::ERR_CONNECTION_CLOSED`. Флаги,
настройки и расширения пользователь открывает руками.

**Кнопка Relaunch на странице флагов** поднимает браузер без
`--remote-debugging-port`. После смены флагов перезапускать командами из шага 1.

**В zsh включён noclobber**: писать `>| файл`, иначе «file exists».

**Переменные окружения через `open -a` не доходят.** Нужен, например, `TZ` —
запускать бинарь напрямую:
`TZ=Europe/Helsinki nohup /Applications/Helium.app/Contents/MacOS/Helium --remote-debugging-port=9222 &`

## Когда всё-таки rodkit

`~/go/bin/rodkit` умеет то же плюс `eval`. Брать его только для диагностики
самой страницы, когда без выполнения JS ответа не получить.

Цена: rodkit ищет элементы JS-хелперами rod, те зовут `document.querySelector`,
а сайт может его подменить и снять стек — в стеке видно `functions.element`.
`pagectl` ходит доменами DOM/Page/Input, мимо JS-окружения страницы, и на
перехвате `querySelector` даёт ноль вызовов.

`rodkit eval` оборачивает аргумент в `() => (...)`, поэтому нужен expression:
многострочный код писать как `(()=>{ ... })()`.

`RODKIT_CONSOLE=1` включает сбор консоли, а вместе с ним домен Runtime — после
этого детекторы ставят `isAutomatedWithCDP: true`. Только для отладки, и не в
том прогоне, результат которого показываешь пользователю.

## Почему так, а не антидетект-браузер

Профиль настоящий: история, куки, шрифты, видеокарта — ничего не подделывается,
поэтому и рассыпаться нечему. Camoufox и прочие подставляют сгенерированную
личность, и там нет логинов пользователя.

Ввод уже человекоподобный: курсор идёт дугой Безье, клик попадает мимо центра
элемента, текст набирается посимвольно настоящими key-событиями с Shift где
надо, кириллица — через раскладку ЙЦУКЕН. Механика ввода общая у обоих
инструментов (пакет `human`), и через rodkit она даёт `isBot: false` на
`deviceandbrowserinfo.com/are_you_a_bot_interactions`. Через pagectl тот же
прогон до конца не доведён: упёрся в недоступность их сервера, не в код.

Подробности замеров и история правок — в памяти, `rodkit-live-helium`.
