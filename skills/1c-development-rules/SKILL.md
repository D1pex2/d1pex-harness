# Правила любого проекта 1С

Применяй к любой конфигурации, расширению, обработке, отчету и другому исходнику 1С независимо от имени клиента и расположения проекта.

До анализа или изменения прочитай [правила работы с 1С](references/rules.md). Хук добавляет их полный текст при первом действии с 1С в чате. Если правила не загрузились, останови зависимую работу и сообщи об этом; не восстанавливай их по памяти.

Правила разделены по операциям: код и запросы, навигация code-index, метаданные, интерфейс форм, расширяемые формы и известные ловушки инструментов. Применяй нужные разделы, сохраняя ограничения безопасности и согласованный объем.

До первого редактирования выполни раздел "Выбор места изменения до правки": найди и прочитай существующую реализацию, проследи цепочку вызовов, назови файл и процедуру для изменения. Сохраняй действующий механизм проекта; новый обработчик не выбирается только по названию события.

Перед завершением сверь измененные объекты с запросом, проверь контексты BSL, параметры API и запросы подходящими инструментами. Отдельно укажи статическую проверку, сборку, загрузку, обновление базы и проверку пользовательского сценария. Не выдавай одну проверку за другую.

В существующих проектах профиль имеющегося bsl-context под платформу проекта задается локальной конфигурацией агента (например `.codex/config.toml` в Codex или `mcp_config.json` в Antigravity). После смены платформы актуализируй профиль; не используй чужой индекс для worktree. При отсутствии точной версии уточни ее, а не подставляй глобальную молча.
