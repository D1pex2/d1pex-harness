# Правка Open WebUI через браузер

Навык для работы с Open WebUI, когда есть только браузер с вошедшим администратором (Codex in Chrome, встроенный браузер Antigravity или Playwright MCP), а доступа к контейнеру и файлам сервера нет. Адрес сервера и учётные данные берутся из задачи или проекта, в навыке их нет.

Главная мысль: интерфейс Open WebUI умеет молча не сохранить изменение. Всплывающее сообщение об ошибке исчезает за пару секунд, страница после клика выглядит как успех. Поэтому любое "сохранено" подтверждается чтением состояния с сервера, а не видом страницы.

## Запросы к API со страницы

Все проверки делаются через `javascript_tool` на открытой странице Open WebUI. Токен сеанса лежит в `localStorage.token`, его не нужно печатать или копировать куда-либо:

```js
const api = async (path, opts = {}) => {
  const r = await fetch(path, {
    ...opts,
    headers: {
      'Authorization': 'Bearer ' + localStorage.token,
      'Content-Type': 'application/json',
      ...(opts.headers || {})
    }
  });
  const text = await r.text();
  let body; try { body = JSON.parse(text); } catch { body = text; }
  return { status: r.status, body };
};
```

Функция возвращает и статус, и тело: статус нужен, потому что ошибка 400 с понятным текстом (например, "DDGS is unavailable in slim") и есть причина, по которой настройка не сохранилась.

## 1. Серии кликов в редакторе модели и админ-настройках

Редактор модели отрисовывает блоки с запаздыванием. Серия кликов, начатая через 4 с после перехода, однажды прошла мимо: список инструментов не открылся, переключатели остались прежними, при уходе всплыло "Leave site?". С паузой 6-7 с серия из 11 кликов работала стабильно на всех 13 моделях.

Порядок работы:

1. После `navigate` ждать 6-7 с. Меньшая пауза экономит секунды, а промах стоит повторного прохода и проверки всей модели.
2. Перед серией кликов сделать один пробный клик и скриншот: убедиться, что блок раскрылся там, где ожидался. Только после этого запускать пакет кликов (`browser_batch`).
3. Порядок раскрытия блоков держать одинаковым на каждой модели, например: возможности, затем встроенные инструменты, затем список инструментов. Координаты нижних строк зависят от того, раскрыт ли блок выше (например, "Функции по умолчанию"). Другой порядок на одной из моделей сдвинет все следующие клики.
4. Если после серии появилось "Leave site?", значит сохранение не прошло. Не подтверждать уход вслепую: вернуться, сделать скриншот, понять, какой клик промахнулся.

Если правок много и они одинаковые, сначала посмотреть, нельзя ли сделать их через API (раздел 3 описывает такой путь для tools; для моделей есть свои POST-методы обновления). Клики оставлять для случаев, когда API-путь не проверен.

## 2. Проверка, что сохранилось

После каждой серии или каждого "Сохранить" прочитать состояние с сервера:

- модели: `GET /api/v1/models/list` - у нужных моделей проверить поля, которые меняли (например, `meta.capabilities.web_search`, `meta.toolIds`);
- админ-настройки поиска и retrieval: `GET /api/v1/retrieval/config`;
- статус самого запроса сохранения: `read_network_requests` с фильтром по пути (например, `retrieval/config/update`), смотреть код ответа и тело.

Сверять со списком того, что должно было измениться, по каждой модели, а не выборочно. Пример из практики: два "сохранения" веб-поиска в админке выглядели успешными, а `GET /api/v1/retrieval/config` показывал `enable=false` и пустой движок; прямой POST на `/api/v1/retrieval/config/update` вернул 400, потому что выбранный движок недоступен в slim-сборке. Об этом нужно сказать пользователю как о причине, а не повторять клики.

## 3. Обновление кода tool без доступа к контейнеру

Путь через сервер (ssh, `docker cp` во временную статику и загрузка оттуда) может быть отклонён автопроверкой действий и требует доступа, которого нет. Рабочий путь только через API со страницы:

1. Прочитать текущий tool: `GET /api/v1/tools/id/<id>`. Сохранить `id`, `name`, `meta`, `access_control` и `content`.
2. Получить замены из git-диффа локальной версии (старый фрагмент и новый фрагмент для каждого изменённого места).
3. Применить замены к `content` в JS. Код на сервере хранится с CRLF, поэтому многострочный фрагмент с `\n` молча не найдётся. Перед заменой привести переводы строк фрагмента к виду, который в `content`, и для каждой замены проверить число совпадений: ровно одно. Ноль или больше одного - остановиться и разобраться, а не отправлять код.

   ```js
   const eol = t.content.includes('\r\n') ? '\r\n' : '\n';
   const fix = s => s.replace(/\r\n/g, '\n').replace(/\n/g, eol);
   let code = t.content;
   for (const [oldPart, newPart] of replacements) {
     const o = fix(oldPart), count = code.split(o).length - 1;
     if (count !== 1) throw new Error('совпадений ' + count + ': ' + oldPart.slice(0, 60));
     code = code.replace(o, () => fix(newPart));
   }
   ```

4. Сверить результат с локальной сборкой по хэшу. `crypto.subtle` на сайте по http недоступен (это не secure context), поэтому хэш считается FNV-1a по кодовым единицам UTF-16 после приведения переводов строк к `\n`. В браузере:

   ```js
   const fnv1a = s => {
     s = s.replace(/\r\n/g, '\n');
     let h = 0x811c9dc5;
     for (let i = 0; i < s.length; i++) { h ^= s.charCodeAt(i); h = Math.imul(h, 0x01000193) >>> 0; }
     return h.toString(16).padStart(8, '0');
   };
   ```

   Локально тот же хэш даёт `python scripts/fnv1a_utf16.py <файл>` (из папки навыка). Хэши должны совпасть. Не совпали - не отправлять.
5. Отправить: `POST /api/v1/tools/id/<id>/update` с телом `{id, name, meta, access_control, content: code}`, где `id`, `name`, `meta`, `access_control` взяты из шага 1 без изменений. Иначе можно потерять описание tool или права доступа к нему.
6. Повторно прочитать `GET /api/v1/tools/id/<id>`, посчитать хэш `content` и сравнить с локальным. Прочитать `GET /api/v1/tools/id/<id>/valves` и убедиться, что значения Valves не сбросились.

Только после шага 6 можно говорить пользователю, что код tool обновлён.

## Что сообщать пользователю

В итоге называть, что проверено чтением API (какой метод, какие поля, по скольким моделям), а что видно только на скриншоте. Если сохранение отклонил сервер, приводить код ответа и текст ошибки.
